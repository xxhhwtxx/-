# 关键流程与异常处理

## 1. 标准流程

1. 下单：渠道提交订单（含幂等键）
2. 校验：鉴权、参数校验、风控预检
3. 锁卡：按规则选卡并原子锁定库存
4. 发卡：生成履约结果并更新订单状态
5. 回执：通知渠道（Webhook/短信/邮件）
6. 结算：记录结算状态与对账字段

## 2. 幂等与防重

- 下单接口必须携带 `idempotency_key`
- 同渠道 + 同幂等键重复请求直接返回首个结果
- 回调与通知均使用 `event_id` 去重

## 3. 失败补偿

- 锁卡失败：直接返回库存不足，订单置 FAILED
- 发卡过程失败：
  - 可重试错误：进入重试队列，订单维持 PROCESSING
  - 不可重试错误：释放卡库存，订单置 FAILED
- 通知失败：不影响主流程，异步重试并告警

## 4. 库存回滚

- 锁定后未发卡成功必须释放（状态回 AVAILABLE）
- 超时锁自动回收（定时任务）
- 同一张卡禁止二次发放（ISSUED 不可逆）
